# Lead Game Designer：少前情，先行动

2026-10-26。独立设计提案，未确认为最终需求。依据用户反馈与当前实现，不代表已完成玩家验证。

实施更新：本报告记录的是 v0.1 的叙事评估。后续用户明确要求角色养成，当前 v0.2 范围见 [当前 MVP](mvp-minimal.md)。以下为 v0.1 当时的实施情况：短场景直接开局、具体行动、行动后场景与条件回响已在试玩版落地；31 项规则/叙事检查通过，是否更有代入感仍待用户试玩，不由自动检查判断。

## 判断

**少前情有助于进入角色，前提是眼前处境与可做的事仍然清楚。** 少写人物履历，不等于只剩资源按钮。代入感需要玩家先做一件有意义的事，场景随之变化，后续还记得这次行动。像素字体本身不能提供这些。

背景应按需要逐步出现：现在为什么要选，先说；某人是谁、过去发生过什么，等与行动有关时再露出。复杂世界或明确扮演特定人物的游戏可能需要更多前情，本项目暂没有这个必要。

## 现有实现的三个断点

检查了 [app.js](../web/dist/app.js) 的 `intro()`、`choices()`、`feedback()` 与 `playing()`：

1. 玩家开始前先选开局、读规则；开始后仍面对另一层说明，进入动作较慢。
2. 两个按钮主要像资源计划。同一行动没有随处境变化的具体任务，书店和小册容易只是数值标签。
3. 反馈主要重述资金与进度，下一场景几乎不回应上一次动作。结局有账目，却缺少“这是我刚经历的事”的连续性。

因此不建议先增加室友搬家等长前情。先把现有选择改成当下动作，让回响发生在游戏里。

## 可直接采用的第一幕

标题：**周六，早上。**

> 手机亮了：“书店今天缺人，来吗？200 块。”
>
> 桌上压着一张小展通知：下周末截稿。
>
> 旁边是一本空白小册。

行动：**去书店帮忙** / **坐下做小册**。

把金额与开销放在行动旁，小册旁明确“需投入两个周末成册”。必要规则不能为了沉浸而藏起来。姓名年龄放状态栏即可；首局用默认处境，另一种资金起点可留到重玩入口。

### 第一轮：去书店

> 你把旧书摆回架上。一册旅行书里，掉出一张手画的街巷图。
>
> 陈姐收好图，指了指空墙：“下周末，这里会挂大家的小刊。”

随后结算收入。工作路线也留下具体人物和物件，不承担“没做作品就没故事”的价值判断。

### 第一轮：做小册

> 你把早餐摊的招牌和回家那盏灯画在纸上。
>
> 第一页排好时，天已经黑了。你在角落写下“住在这里”。

随后显示这张实际可查看的素材，再结算开销。无需再加一位人物解释你为何创作。

## 第二轮应怎样记得玩家

上轮去书店：

> 陈姐发来展架的照片，上面夹着那张街巷图。你的桌面还是空白小册。今晚截稿。

同时明示：现在开始可以留下素材，但赶不上本次收稿。

上轮做小册：

> 上周画下的招牌还摊在桌上。把这些页订起来，今晚就能交稿。陈姐又发来消息：“今天能来帮忙吗？”

这里不增加新选项，只改变同一选择的具体含义。第三轮继续按已发生事实写：赶上就看见作品上墙；没赶上仍可独自完成；连续工作则延续与书店的熟悉感。不要临时随机编造一段成功或遗憾。

## 本次改动边界

保留三回合、两种行动、资金、截止与记录。调整开场位置、动作标签、选择后的小场景和条件反馈；背景通过人物当前说话与物件逐步显现。行动后先让事情发生，再展示账目，最后由玩家继续。

后置长履历、关系值、NPC 日程、探索地图、任务树、随机剧情池与强制打字等待。前情少也不需要靠隐藏代价或长动画制造未知。

## 三个观察点

- 玩家能否直接开始行动，并说明眼前在权衡什么，而不是先复述设定？
- 第二轮是否认出自己上轮留下的物件或变化，能用一次具体经历解释？
- 工作与创作两条路线，是否都能记住一幕，并愿意做下一次安排？

先用这三点检查修改后的试玩，再决定是否扩充故事。若玩家只记得余额，继续修行动与反馈；无需先加更多前情。

# v0.2 复评：成长结构已经成立，乐趣仍未验证

2026-10-26。用户在第二轮试玩后再次反馈「总感觉差点意思」「现在还是不太好玩」，要求综合参考养成游戏的设计要领。本节是独立复评与下一次实验建议，**未确认为新 MVP，也未修改线上玩法**。

## 判断与前两轮的偏差

当前更接近一份可操作的升级流程。能力门槛、新任务、身份与后续使用均已实现，但这些事实不能证明玩家感到自主、期待或在意这个角色。前两轮把反馈过快翻译为功能清单：缺代入就补场景，缺养成就补等级与身份；核心体验尚未成立时，继续实现完整版本增加了返工。

文字界面降低了美术和操作实现量，仍需设计投入、变化、动机、选择与后果如何相互作用。本版缺少乐趣，首先应检查设计，不以「MVP 小」解释或证明必须堆更多系统。

## 现有代码能够证明什么

| 已验证的实现事实 | 对体验的诊断，仍需玩家验证 |
| --- | --- |
| [行动定义](../web/dist/engine.js) 为固定收入、成本、经验与门槛；技能 2、4 加一次实际任务分别开放事件 | 玩家可能很快看见全部路线，点击是在确认预期，少有重新判断局面的需要 |
| [事件解锁](../web/dist/engine.js) 只检查自己的能力、已完成任务与既有机会 | 世界主要在等玩家达标后发奖励，缺少独立发生、值得角色介入的事情 |
| [任务叙事](../web/dist/story.js) 自动完成构图、沟通、找书与推荐，行动后直接结算 | 玩家决定是否接任务，却没有参与任务里有意思的处理；更多旁白不会自动增加行动权 |
| 身份后的机械变化主要是任务标题、收入与呈现；同项任务的身份场景固定 | 身份可能更像毕业证，未充分改变下一次想怎样安排生活 |
| 题材沿用书店与小册，用户只确认了养角色及能力触发事件 | 「想长成谁」仍未建立；不能把两个职业称号当作用户愿望 |

没有总分不自动产生自主感；确定结算也不自动导致无聊。要验证的是，玩家是否有在意的目标、应对事情的方法与能影响后续的决定。

## 一手材料与可借鉴的原则

这些是参考，不是成功配方，也不要求本项目复制完整系统。

| 参考 | 原材料明确说明的内容 | 对本项目的设计推论 |
| --- | --- | --- |
| Eric Barone 的 [Stardew Valley 开发者访谈](https://apps.apple.com/us/story/id1440669118) | 重复活动中，玩家次日变得更有能力或效率；奖励安排也要避免把人推向无趣操作 | 成长应改变下一次做事的体验；收益设计要检验实际鼓励了什么行为 |
| Sarah Northway 的 [Exocolonist 开发深挖](https://www.gamedeveloper.com/programming/deep-dive-the-narrative-octopus-of-i-was-a-teenage-exocolonist) | 共同主线按时间发生，结果受能力与决定影响；另有活动与关系事件 | 能力可决定特殊事件，也应改变面对共同事件的应对方式；世界不必全靠升级推进 |
| Hanako Games 的 [Long Live the Queen 官方说明](https://hanakogames.itch.io/long-live-the-queen) | 培养技能并决定如何面对危机，同一挑战可由多种方法解决 | 可以只借鉴「不同本领产生不同处理方式」，无须引入大量属性或死亡压力 |
| Failbetter 的 [StoryNexus 开发日志](https://www.failbettergames.com/news/storynexus-developer-diary-2-fewer-spreadsheets-less-swearing) | 小段事件由状态控制，选择又改变状态，以此组织后续内容 | 事件本身需要选择与后果，不能把事件仅当作领取新行动的通知 |
| François Alliot 的 [Reigns 设计深挖](https://www.gamedeveloper.com/design/game-design-deep-dive-creating-an-adaptive-narrative-in-i-reigns-i-) | 依据局面与先前决定调整后续内容，并避免过近重复 | 应比较「选择改变了下一局面多少」，而不只计事件数量；随机抽卡不是必要前提 |

[Ryan、Rigby 与 Przybylski 的四项研究](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf)把游戏中的自主感、胜任感等与乐趣及后续游玩联系起来。这提供检查体验的角度，不证明本项目玩家不喜欢的具体原因。

## 用来检查下一轮的四个问题

1. **期待：** 玩家有没有一件自己想完成的事？它可以很小，不需要提前选择终身职业。下一步应有方向，同时留有发现局面的空间。
2. **成长：** 学过的本领是否让同一件事多一种办法、少一点依赖、或能做出不同结果？仅把数字增加到下一道门槛不足以验证。
3. **介入：** 事情发生时，玩家是否能决定如何处理？不要求微操作或额外小游戏，但关键决定应由玩家作出。
4. **归属：** 下一次遇见人物、物件或处境时，是否认得自己此前的处理？后果既要可追溯，也要对接下来有用途。

这四项是本项目的检查问题，不是所有养成游戏必须同时具备的清单。局部最优策略可以带来学会玩法的满足；需要避免的是，把所有人生追求都换成同一种收入排名。也不靠隐藏代价或随机失败阻止玩家计算。

## 下一次建议：先试一个事件，而非继续扩两条职业线

保留现有短场景、文字界面、能力、资金及事实记录。先用三次有效行动测试「准备—应对—后续」；这是纸面实验，**不是把正式游戏重新缩回三回合**，也不代表已经决定制作市集题材。

```mermaid
flowchart LR
    A[眼前有一件在意的事] --> B[选择准备，练出本领]
    B --> C[共同事件发生]
    C --> D[本领改变可选的处理方法]
    D --> E[结果留下新的请求与安排]
    E --> B
```

沿用现有街区，只为说明结构：

- **准备：** 已知周末有街坊市集，早餐摊需要帮忙。玩家可练画清楚的指示，或学整理与安排摊位。说明各自能帮上什么，保留改变想法的余地。
- **应对：** 市集遇雨，摊位改到书店狭窄的门廊。所有人都会遇见这件事；能力开启不同方法：画引导牌让人找到新位置，或重新安排书桌和取货顺序。每种方法有明确的材料、空间或时间代价；尚未学会的人仍可请陈姐协助基础安排。玩家自己选怎样处理，不由旁白自动宣布全部做好。
- **后续：** 看见实际方案留下的布置、招牌或交接记录。新的请求来自实际处理：有人想请你画下一张牌，或希望你安排下一次摆摊。玩家再决定接着深入，还是去补上这次感到不足的本领。

下次只准备一个共同事件、两种处理方法和一条有用途的后续变化。暂不增加第三项能力、大量事件、关系数值或全人生内容。世界事件可以确定发生，已知代价应明确；不知道下一幕会发生什么，与不知道按钮会扣多少钱是两回事。

验收从「技能门槛正确」改为观察：玩家是否会说「我想这样处理，所以接下来想学这个」，是否主动想看看后续，重试时能否说明想换哪个做法及原因。说明理由并不单独证明有趣，主动继续玩的意愿也应一起看。

## 仍未确认

用户已确认养角色，但尚未确认更在意应对挑战、发现未知人生，还是逐渐形成自己认同的人格与身份。书店和画画的题材也未被认领为愿望。下一次实验应允许这些偏好浮现；不要据此擅自宣告新的职业线或完整 MVP 已确定。
