# 两次周五：最小可玩片段

这是一次独立的玩法验证。原有秋季版本保留，新片段在 `/fridays/`，使用独立本地存档。

要验证的是：玩家是否愿意因为上次的经历和自己想过的夜晚，主动尝试另一种做法。电影只是本次测试载体，不代表未来必须做放映社经营。

## 实际范围

- 同一座虚构中国大学、同一间203教室，三位同学。
- 10月11日第一次周五，跟着小满调画面或招呼人，再处理一次迟到。
- 10月15日、17日两段课余，从看片、试教室、吃饭、一起走路中各做一件。上课和普通日子通过简短过场经过，不等待真实秒数。
- 10月18日第二次周五，自己选片、排座、处理林野到来的当下。
- 不同准备提供新方法；第一次留下的印象影响第二次别人如何配合、是否自己加入谈话。
- 没有统一评分。安静看完、一起聊天、散场还在走廊说话都是有效夜晚。处理方式涉及谁错过镜头、谁要补前情等具体取舍。

共8次输入，其中一次是回应下周邀请。选择直接进入下个可处理的场景，保留上一动作的反馈。房间、座位与结尾人物位置对应真实状态。结尾表示这一小段结束，不预先承诺后续内容已实现。

## 实现与扩展窗口

`engine.js` 保存确定性的选择记录、知识与今晚安排；`story.js` 提供状态相关的情境和人物反应；`art.js` 根据安排与结尾状态画房间；`app.js` 负责输入、恢复进度和呈现。存档以历史重放校验，新的片段与旧版互不覆盖。

当前不做完整学期、属性刷取、自动过日子、自由聊天生成、更多国家、分享模板或排行榜。需要扩展时，先沿具体角色/兴趣增加情境与方法，再决定是否值得抽象成完整养成系统。

## 验证

纯规则检查覆盖准备限制、实际可用方法、过去经历造成的分歧、结尾状态及存档恢复。浏览器检查完成完整走法、另一种准备产生的动作差异、重新开始、刷新恢复及窄屏阅读。流程通过不代表趣味性已被证明，仍以真实试玩反馈为准。
